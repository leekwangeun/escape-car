# 차량탈출 AI 이야기 서버

차 앱이 정한 퍼즐 정답(규칙 엔진, 예: "풍량 5단")을 받아, 그 장치를 다루는 문제(계산, 영어, 규칙 찾기, 추론)를 **문제은행**에서 아이 나이에 맞게 무작위로 뽑고, 그 문제로 이어지는 이야기를 아이가 고른 친구의 말("나")로 Claude 또는 Gemini로 써서, 검사를 통과한 장면만 차로 돌려보냅니다.
문제은행(약 300개, `app/question_bank.json`)은 문제마다 차 기능 하나(바람 세기, 온도, 독서등, 열선, 에어컨, 내기 순환, 앞 유리 성에 제거)를 다루며, Claude로 한 번 만들고 코드와 다른 모델로 검산해 둔 것이라, 판마다 AI가 문제를 새로 만들지 않습니다. 서버나 AI가 실패하면 차 앱은 앱에 든 은행 사본(`assets/question_bank.json`)에서 문제를 뽑아 그대로 진행합니다.

## 흐름

```
차 앱 (부모 준비 화면, 판이 시작될 때)
  └ POST /v1/episode  { 나이 단계, 시간, 계절, 고른 친구, 정답 키 목록 }   ← 이름, 목소리, 위치, 자유 문장은 보내지 않음
       └ Claude 또는 Gemini (구조화 출력, 정해진 JSON 틀) → 검사기 → 통과한 장면만 응답
  ← 다음 판 이야기를 기기에 저장해 두었다가, 같은 설정으로 시작하면 바로 사용 (차 안에서 기다리지 않음)
```

- **정답 키**: 퍼즐마다 한 칸이고, 칸에는 계획한 정답 키와 퍼즐을 시작할 때 차 상태 때문에 앱이 바꿔 낼 1순위 키(반대 방향 문제)가 함께 들어갈 수 있습니다. 작가는 두 장면을 다 쓰고, 앱은 실제로 낸 쪽을 읽습니다. 키 형식은 `Q:<문제 종류>:<장치>:<값>`, 예: `Q:MATH:FAN:5`(답이 5인 계산 문제, 풍량 5단으로 답함), `Q:REASON:AC:1`(상황을 듣고 에어컨을 켜서 답함), 그리고 벨트 미션 `BELT`.
  - 문제 종류: `MATH`(계산), `ENGLISH`(숫자 영단어나 글자 수), `PATTERN`(규칙 찾기), `REASON`(추론: 곤란한 상황을 듣고 그 상황을 풀 차 기능을 찾아 조작)
  - 장치와 값: `FAN` 풍량 1~8단, `TEMP_UP`/`TEMP_DOWN` 퍼즐 시작 때보다 1~3도 올리기/내리기, `LIGHTS` 켜진 독서등 1~4개, `SEAT_HEAT` 운전석 열선 1~3단
  - 추론의 장치와 값(`quiz.REASON_ACTIONS`): 켜기는 1, 끄기는 0, 방향만 있는 조작은 1. `AC` 에어컨 켜기/끄기, `RECIRC` 내기 순환 켜기/끄기, `DEFROST` 앞 유리 성에 제거 켜기, `TEMP_UP`/`TEMP_DOWN` 온도 올리기/내리기, `FAN_UP`/`FAN_DOWN` 바람 세게/약하게, `SEAT_HEAT_ON`/`SEAT_HEAT_OFF` 운전석 열선 켜기/끄기, `LIGHT_CHILD` 뒷자리 독서등 켜기, `LIGHTS_OFF` 독서등 모두 끄기
- **검사기** (`app/checker.py`, `app/quiz.py`)
  1. 틀: 길이(가장 어린 나이 단계 기준), 빠진 장면
  2. 말: 무서운 말, 차에서 위험한 말(문, 창문 열기, 벨트 풀기, 출발, 기어 등), 개인정보 질문, 영어와 주소(영어 문제의 단어 하나만 예외), 존댓말(`~요`, `~니다`, `~죠`)
  3. 다시 풀기: 계산식은 직접 계산하고, 수열은 다음 수를 구하고, 영어는 숫자 단어 표나 글자 수로 답을 구해서 정답 값과 같아야 함. 식의 수가 문제 문장에 모두 있어야 함
  4. 나이 난이도: 4~6세는 5 이하 수로 한 번 셈, 7~9세는 10 이하 수로 한 번 셈, 10~12세는 곱셈까지(`quiz.LEVELS`). 넘으면 버림
  5. 정답 새지 않기: 정답 수(숫자, "다섯 개" 같은 말)가 말풍선, 이야기, 문제, 힌트에 나오면 안 됨
  6. 추론: 문제 문장이 나이별 길이(4~6세 70자, 7~9세 90자, 10~12세 120자, `quiz.REASON_MAX`) 안이어야 함. 아이가 상황을 듣고 기능을 스스로 찾도록 이야기(speech)에 버튼 이름과 직접적인 조작 지시("켜기", "켜 줘", "눌러 봐" 등)가 없어야 함
  7. 말풍선: 그림 옆 말풍선(bubble)에 버튼 이름("성에", "독서등" 등)이나 "켜기", "끄기"가 없어야 함
  8. 등장인물: 고른 친구 말고 다른 도감 친구, 루미, 예전 친구(펭귄 선장 등)의 이름이 대사와 그림 설명(art) 어디에도 나오면 안 됨. 첫인사에는 고른 친구가 자기 이름을 말해야 함
  9. 푼 뒤 한 줄(result): 길이(4~6세 70자, 그 밖 90자), 무서운 말, 다른 인물 이름. 아이가 이미 정답을 넣은 뒤라 정답 버튼 이름과 수는 써도 됨. 걸리면 그 줄만 빠지고 앱이 기본 칭찬을 말함
- 답을 어느 버튼에 넣을지와 "안전 지킴이에게 알려 줘"라는 말은 AI가 쓰지 않고 차 앱이 문제 뒤에 붙입니다(`Lines.ask`). 그래서 AI 문장이 아이를 엉뚱한 버튼으로 보낼 수 없습니다.
- **문제은행** (`app/bank.py`, `app/question_bank.json`)
  - 만들기: `.\.venv\Scripts\python -m tools.make_bank --md 목록.md` (Claude 키 필요, 호출 비용이 듭니다). 모자란 칸만 채우고 이미 있는 문제는 그대로 둡니다. 만든 뒤 차 앱의 `assets/question_bank.json`에도 복사합니다.
  - 넣기 전 검사: 코드로 답 다시 구하기와 나이 난이도(`bank.problems`), 다른 모델(Haiku)이 문제 문장만 보고 같은 답을 내는지(추론은 13가지 조작과 아이가 할 만한 다른 조작을 섞은 보기에서 5번 중 4번 이상 같은 조작을 고르는지), 같은 문제가 이미 있는지.
  - 추론 문제의 말(`bank.reason_problems`): 아이가 고른 친구가 "나"로 하는 반말로 쓰고 "알맞은 차량 버튼을 찾아 나를 도와줘!"(운전석 열선 문제는 "알맞은 차량 버튼을 찾아 안전 지킴이를 도와줘!")로 끝남. 어느 친구가 어느 장소에서 말해도 맞도록 친구 이름, 몸 특징(꼬리, 털 등), 장소에 묶인 물건, 까닭(감기, 줄넘기 등)은 쓰지 않음. 까닭은 문제 앞 이야기가 정함. 존댓말은 숫자 문제까지 모든 문제와 힌트에서 금지. 정답 버튼 이름과 "기능"이라는 말은 쓰지 않음. 앱은 나오는 조건(`quiz.REASON_WHEN`)이 맞을 때만 문제를 내고 계절과 낮밤을 모르므로, 그 조건이 보장하지 않는 차 상태(다른 버튼, 단계, 개수, 차 안 온도)와 날씨, 계절, 낮밤은 단정하지 않음.
  - 서버는 켤 때 은행 전체를 다시 검사하고, 깨진 문제가 하나라도 있으면 켜지지 않습니다. 손으로 고친 뒤에는 서버를 켜 보거나 `pytest`로 확인합니다.
  - 장치마다 내는 종류(`quiz.KINDS_FOR`): 풍량과 독서등은 계산, 영어, 규칙 찾기, 열선은 계산과 영어, 온도는 계산, 영어, 추론, 에어컨처럼 켜고 끄는 기능은 추론만. 계산, 영어, 규칙 찾기 문제 문장에는 그 장치의 말(`quiz.DEVICE_WORDS`)이 꼭 들어갑니다.
  - 추론은 조작마다 나이별로 3개씩 있고, 4~6세에게는 내기 순환과 온도 내리기를 내지 않습니다(`quiz.REASON_NOT_LITTLE`).
  - 판마다: 퀴즈 키마다 같은 장치, 같은 종류, 같은 정답, 같은 나이의 문제를 무작위로 하나 뽑습니다(그 나이 문제가 없으면 더 어린 나이 문제). 은행에 맞는 문제가 없는 키는 차 앱이 자기 문제로 진행합니다.
- **규칙 파일** (`app/story_rules.toml`): 길이 제한, 금지 패턴, 벨트 미션의 장면 설명이 여기 있습니다. 서버가 시작할 때 파일을 검사해서, 모르는 항목 이름, 깨진 정규식, 빈 단어 묶음이 있으면 서버가 뜨지 않습니다(오타가 검사를 몰래 약하게 만들지 않도록).
- 검사 부품(금지 패턴, 길이, 꼭 넣을 말, 판정 범위)과 표본 측정 명령은 [textgate](https://github.com/leekwangeun/textgate) 라이브러리를 씁니다. 나이별 말 길이와 안전 지킴이 규칙처럼 차량탈출에만 있는 규칙은 `app/checker.py`에 있습니다.
- 판 전체 문장(제목, 첫인사, 끝 인사)에 문제가 있으면 그 초안은 버립니다. 장면 하나만 문제면 그 장면만 빼고, 차는 그 장면을 기본 문장으로 진행합니다. 한 번 더 써 보고 더 깨끗한 초안을 고릅니다.
- **기록**: `data/episodes.jsonl`(보낸 이야기), `data/reports.jsonl`(부모의 이야기 신고, 같은 사유 중복 신고 제외·IP별 횟수 제한). 설치 ID와 IP 원문은 기록하지 않습니다.
- **비용 제한**: 설치 하나당 하루 20편, 주소 하나당 하루 200편, 서버 전체 하루 300편 (`data/daily_limit.json`에 해시 카운터로 저장되어 재시작 뒤에도 유지, 환경 변수로 조정)
- **그림·음성 자동 정리**: 생성된 `data/images/{storyId}/` 폴더는 기본 24시간(`STORY_IMAGE_TTL_HOURS`), `data/audio_cache/*.wav` 음성 캐시는 기본 72시간(`STORY_AUDIO_TTL_HOURS`, 최대 `STORY_AUDIO_MAX_FILES`개)이 지나면 자동으로 지워집니다. `/v1/speak`도 합성 전에 금칙어와 주소를 먼저 걸러 냅니다. 이야기 창고에 쌓인 이야기는 그림과 목소리를 창고에 따로 두므로 이 정리와 상관없습니다.

## 이야기 창고 (재사용)

검사를 통과한 이야기를 쌓아 두었다가 다른 차가 다시 쓰게 하는 기능입니다. `STORY_LIBRARY_BUCKET`(S3)이나 `STORY_LIBRARY_DIR`(개발용 로컬 폴더)이 없으면 꺼져 있고, 서버는 위에서 설명한 대로만 동작합니다.

- **무엇을 쌓나**: 창고가 켜져 있으면 `/v1/episode`로 만든 **Claude 이야기를 모두**(소원 이야기 포함) 글과 그림까지 쌓습니다. Gemini가 쓴 이야기는 쌓지도 내보내지도 않습니다(`STORY_LIBRARY_MODELS`, 기본 `claude`: 글 모델 이름이 이 접두어로 시작할 때만, 빈 값이면 모두). 빠진 장면이 있거나 시간대 말(아침, 저녁, 밤, 새벽, 노을)이 들어간 이야기는 쌓지 않습니다.
- **찾는 열쇠**: 함께할 친구, 아이 나이, 기다릴 시간, 소원(장소와 이야기 종류가 든 한 문장), 계절. 교훈은 열쇠가 아닙니다. 칸은 친구, 가장 어린 나이, 분, 소원으로 나뉘고 칸마다 `STORY_LIBRARY_CAP`편까지 둡니다. 나이 조합과 계절은 꺼낼 때 맞춰 봅니다(계절 없이 쓴 예전 이야기는 어느 계절에나 나갑니다).
- **시간대와 계절**: 작가에게는 계절만 알려 주고 시간대는 알려 주지 않습니다(창고가 꺼져 있어도 같습니다). 창고에 쌓을 이야기에는 바깥 기온도 알려 주지 않습니다.
- **교훈**: 같은 열쇠로 쌓인 이야기가 이미 있으면, 새로 쓸 이야기에는 그 칸에 아직 없는 교훈을 골라 줍니다. 같은 선택으로 여러 번 하면 교훈이 다른 이야기가 쌓입니다.
- **저장 위치**: `library/{친구}/{나이}/{분}m[/w-{소원 해시}]/{storyId}/` 아래에 `story.json`(차가 받는 이야기), `draft.json`(작가 초안과 요청), `img/{이름}.webp`(그림), `voice/{줄 키}.wav`(그 이야기의 대사 녹음). 대사 녹음은 `/v1/speak`로 읽은 줄에 이야기 글이 들어 있으면 함께 보관하고(창고에 넣기 전에 읽은 줄도 넣을 때 옮김), 다음에 같은 줄을 읽을 때는 TTS를 다시 부르지 않고 창고에서 꺼냅니다. 신고된 이야기는 `blocked/{storyId}.json`으로 표시합니다. 모두 `STORY_LIBRARY_PREFIX` 아래에 있습니다. 설치 ID, IP, 시간대는 저장하지 않습니다. 소원은 찾는 열쇠라서 저장하지만, 똑같은 소원을 보낸 차에만 나가므로 다른 가족에게 새로 알려지는 것은 없습니다. 어느 차가 무슨 이야기를 들었는지는 서버가 아니라 각 차가 기억합니다.
- **`POST /v1/library`**: 차가 같은 열쇠의 이야기 후보를 달라고 합니다(소원 없는 칸은 `STORY_LIBRARY_CANDIDATES`편까지, 소원 칸은 30편까지). 서버는 후보만 주고, 어느 것을 쓸지와 퍼즐 정답은 앱의 규칙 엔진이 정합니다. 앱은 이 차에서 이미 들은 이야기를 빼고 고르고, 맞는 것이 없으면 `/v1/episode`로 새 이야기를 씁니다. 소원 없는 칸의 이야기가 `STORY_LIBRARY_MIN`편보다 적으면 가끔(`STORY_LIBRARY_FRESH` 확률) 후보 없이 돌려보내 새 이야기를 쓰게 합니다. 소원 칸은 그러지 않고 있으면 늘 줍니다. 주소 하나당 하루 `STORY_LIBRARY_PER_IP`번까지 부를 수 있습니다.
- **그림**: 창고 이야기의 그림 주소는 처음과 같은 `/v1/images/{storyId}/{이름}.webp`입니다. 24시간짜리 그림 폴더에서 지워진 뒤에는 창고의 그림을 내줍니다.
- **신고**: 부모가 신고하면 그 이야기는 창고에서 빠지고 더 이상 후보로 나가지 않습니다. 주소 하나가 하루에 빼 낼 수 있는 이야기는 `STORY_LIBRARY_BLOCKS_PER_IP`편입니다.
- **다시 검사**: 서버가 켜질 때 창고의 이야기를 모두 지금 규칙으로 다시 검사하고, 읽을 수 없거나 허용되지 않은 모델이 쓴 이야기, 신고된 이야기, 검사에 걸리는 이야기는 건너뜁니다. 창고를 읽다가 실패하면 서버는 창고 없이 뜹니다. 이야기는 16개씩 한꺼번에 읽고, `STORY_LIBRARY_LOAD_SECONDS`(기본 60초)가 지나면 그때까지 읽은 이야기만으로 서버를 띄웁니다(신고된 이야기는 먼저 읽으므로 그래도 나가지 않습니다). 창고에 새로 쌓는 이야기도 같은 검사를 통과해야 쌓이므로, 쌓인 이야기가 다음 시작에 조용히 빠지는 일이 없습니다.
- **환경 변수**: `STORY_LIBRARY_BUCKET`, `STORY_LIBRARY_PREFIX`(기본 빈 값), `STORY_LIBRARY_DIR`, `STORY_LIBRARY_MODELS`, `STORY_LIBRARY_CAP`(200), `STORY_LIBRARY_MIN`(30), `STORY_LIBRARY_FRESH`(0.3), `STORY_LIBRARY_CANDIDATES`(10), `STORY_LIBRARY_PER_IP`(500), `STORY_LIBRARY_BLOCKS_PER_IP`(5), `STORY_LIBRARY_LOAD_SECONDS`(60). `.env.example`에 있습니다. S3를 쓸 때 AWS 리전(`AWS_DEFAULT_REGION`)과 키는 boto3 표준 환경 변수를 따릅니다([배포_방법.md](배포_방법.md)).

## 이야기 소원과 그림 (맞춤 이야기)

- 부모 준비 화면의 **오늘의 이야기 소원**에 듣고 싶은 이야기를 한 문장(60자까지) 적거나 추천 칩을 고르면, 앱이 `wish`와 `pictures: true`를 보냅니다.
- 서버는 소원을 먼저 검사해서 무서운 말, 차에서 위험한 말, 개인정보가 있으면 모델을 부르지 않고 422(`wish_rejected`, 이유 포함)로 돌려보냅니다. 소원 글은 기록 파일에 남기지 않습니다(있었는지만 남김).
- 작가는 소원을 오늘의 세계로 삼아 이야기를 쓰고, `world`(세계 한 줄)와 `art`(표지, 퍼즐마다 한 장, 마지막 장면의 그림 설명)도 씁니다. 문제 종류와 정답은 그대로 규칙 엔진이 정합니다.
- 그림 설명에는 정답 단서(위쪽/아래쪽, 왼쪽/오른쪽, 안/밖, 자리 이름, 버튼 이름)가 들어가면 안 됩니다. 검사기(`checker.art_problems`)가 그런 설명을 빼고, 빠진 그림 자리는 앱의 기본 그림으로 나옵니다. 정답은 친구의 말로만 알려 줍니다.
- 그림은 Gemini 이미지 모델(`IMAGE_MODEL`, 기본 `gemini-nano-banana-2.1`)이 `app/art`의 참고 그림 2장(친구 9명 모델 시트, 클레이 장면)을 보고 같은 캐릭터, 같은 그림체로 그립니다. 그림 속 인물은 고른 친구 한 명입니다. 여러 장을 동시에 그리고, 실패한 그림만 빠집니다. 앱은 `GET /v1/images/{storyId}/{name}.webp`로 받아 기기에 저장합니다.
- 벨트 딸깍 미션 칸은 두 장을 그립니다. 먼저 친구 9명이 탐험대 카시트에 앉은 기준표(`app/art/ref_belt_before.jpg`)를 함께 보고 그 장소에 놓인 카시트에 고른 친구가 벨트를 아직 안 끼운 모습(`p3`)을 그리고, 그 그림을 고쳐 딸깍 끼우고 손을 흔드는 모습(`p3_ok`, 기준표 `ref_belt_after.jpg`)을 만듭니다. 앱은 미션을 마치면 `_ok` 그림을 보여 주고, 없으면 표지를 보여 줍니다.
- 그림은 과한 3D 렌더 대신 손으로 빚은 점토 인형을 찍은 느낌으로 그리게 하고, 반짝임, 빛 번짐, 배경 흐림, 과한 장식 같은 'AI 그림 티'는 매번 금지합니다(`painter.py`의 `LOOK`, `NOT_AI`).
- 키 없이 흐름만 볼 때 `python -m tools.dev_server`는 소원을 제목에 넣고, 그림 자리에 색 카드를 그려 줍니다.
- 추천 칩(이야기 종류)은 보물찾기, 구조대, 탐정 놀이, 수리하러 가기, 축제 준비, 발명 대회입니다. 어떤 장소를 적어도 어울리고, 친구 도감 밖의 캐릭터가 필요 없는 종류만 둡니다.

## 오늘의 교훈

- 앱은 이야기를 요청할 때마다 교훈 하나를 무작위로 골라 `lesson`으로 보냅니다: `COURAGE`(용기), `CARE`(신중함), `CREATIVITY`(창의), `GRIT`(끈기), `TEAMWORK`(협동), `SHARING`(나눔), `HONESTY`(정직), `THANKS`(감사), `PROMISE`(약속), `FRIENDSHIP`(우정). 목록 밖의 값이면 422로 돌려보냅니다.
- 교훈은 이야기 종류와 따로 정해지므로, 작가는 그 종류 안에서 친구의 행동으로 보여 주고 설교하듯 말하지 않습니다. 정직처럼 누가 실수하는 교훈은 혼나는 장면 없이 솔직하게 말하고 다 같이 고치는 것으로 끝냅니다. 꼬마 탐험대(4~6세)가 타면 교훈 낱말 대신 풀어 쓴 말(예: 끈기는 "포기하지 않는 마음")로 말합니다(`prompt.py`의 "오늘의 교훈" 규칙, 낱말과 풀어 쓴 말은 `models.LESSON_LABEL`).

## 고른 친구와 푼 뒤 한 줄

- 앱은 아이가 고른 친구(`friend`: `BANTE`, `KONYANG`, `RIA`, `TUBUGI`, `PAPPI`, `POTTO`, `IO`, `SSOLRANG`, `CASPIN`)를 보냅니다. 이야기 전체를 그 친구가 "나"로 탐험대장에게 들려주고, 장면에는 그 친구 한 명만 나옵니다(`models.FRIEND_LABEL`: 이름, 동물, 상징, 말버릇). 말버릇이 없는 희귀 친구는 말버릇을 새로 만들지 않습니다.
- 장면마다 문제 앞 이야기(`speech`)는 친구가 목표를 위해 하던 일에서 곤란한 일이 생긴 까닭을 들려주고, 정답을 넣은 순간 읽는 푼 뒤 한 줄(`result`)은 차에서 바뀐 것, 이야기 속 결과, 목표까지 남은 것을 말합니다.
- 끝 인사는 탐험 배지를 줄 때의 한 가지(`treasureBadge`)뿐입니다. 어느 퍼즐에나 쓰던 칭찬과 글로브박스 선물 인사는 없습니다.
- 규칙 전체는 `현대기아 앱공모전/차근차근탐험단_이야기프롬프트_규칙안.md`에 있습니다.

## 루미 목소리 (동화 낭독)

- 앱의 모든 대사는 Gemini 음성 모델(`TTS_MODEL`, 기본 `gemini-3.8-flash-tts`)이 그림책 읽어 주는 이야기꾼 목소리로 읽습니다. 차의 목소리(Pleos TextToSpeech)는 앱에서 쓰지 않습니다(속도, 높낮이, SSML을 조절할 수 없어 뉴스처럼 읽기 때문).
- 목소리는 `TTS_VOICE=ko-kr-storyteller-4`(확장 목소리 목록의 한국어 이야기꾼, 27세 여성, 서울말), 말투는 `TTS_STYLE`(영어 지시문)입니다. 목소리 이름이 있는지는 `python -m tools.tts_voices <이름>`으로 봅니다(목록만 조회, 합성 없음).
- **대사 그대로 합성**: 앱은 말할 문장을 이어 붙인 그대로(이야기 + 문제 + 앱의 안내 한 줄, 첫인사 + 공조 오토 안내 등) `POST /v1/speak {installId, text}`로 보내고 WAV(24kHz, 모노, 16비트)를 받아 틉니다. 말투 지시는 대사와 섞지 않고 `speech_metadata.style`에만 넣습니다(모델은 `text`를 글자 그대로 읽으므로 섞이면 지시문을 소리 내 읽습니다).
- **캐시 두 겹**: 서버는 `data/audio_cache/{sha256(모델|목소리|스타일 + 대사)}.wav`에 두고 같은 대사·목소리·스타일이면 다시 합성하지 않습니다(같은 줄을 두 차가 동시에 물어도 한 번만). 앱도 받은 녹음을 기기(`files/voice_cache`)에 둡니다. 판이 시작될 때 그 판의 이야기·문제·정답 뒤 한 줄·끝인사를 미리 받아 두고, 힌트는 누를 때 받습니다(아무도 안 듣는 줄은 합성하지 않음).
- **힌트 미리 녹음**: 퀴즈 힌트는 문제은행 문장 그대로라서 미리 녹음해 `data/hint_voice/`에 둡니다(볼륨 안, 지우지 않음). `/v1/speak`는 이 폴더를 가장 먼저 보고, 있으면 TTS를 부르지 않습니다. 대사 글자로만 찾으므로 `TTS_MODEL`을 바꿔도 그대로 나옵니다. 녹음은 이야기 목소리와 하루 한도가 따로인 Lite 모델(`gemini-3.8-flash-lite-tts`)로 하고, 한 번에 80줄씩, 하루 한도에 걸리면 멈추고 다음 실행에서 이어 갑니다.
  ```bash
  docker compose exec story python -m app.hint_voice          # 몇 줄 남았는지만 보기 (호출 없음)
  docker compose exec story python -m app.hint_voice --yes    # 남은 힌트 80줄 녹음
  ```
- **키 순서**: 무료 키 `GEMINI_API_KEY`로 먼저 합성합니다. 무료 키는 하루 `TTS_DAILY_MAX`(기본 100)번까지만 부르고, 429가 오면 다시 시도하지 않고 멈춥니다(하루 한도면 다음 날까지, 분당 한도면 1분). 무료 키가 한도에 걸리거나 어떤 오류든 나면 유료 키 `GEMINI_API_KEY_PAID`로 **한 번** 더 시도하고, 넘어갈 때마다 서버 로그에 `voice: free key ... retrying once with the paid key`를 남깁니다. 유료 키에는 횟수 제한이 없습니다. 유료 키가 비어 있으면 넘어가지 않습니다.
- **소리가 없을 때**: 두 키가 모두 실패하거나 서버에 붙지 못하면, 기기나 서버에 남은 녹음이 있으면 그것을 틀고, 없으면 그 대사를 화면에 자막으로 보여 줍니다.
- **남용 막기**: 유료 키에 제한이 없으므로 `/v1/speak`는 대사 600자까지, 설치 하나당 하루 400줄(`SPEAK_DAILY_PER_INSTALL`), 주소 하나당 하루 2000줄(`SPEAK_DAILY_PER_IP`), 서버 전체 하루 20000줄(`SPEAK_DAILY_TOTAL`)로 막습니다.
- `TTS_MODEL=off`로 끄면 모든 대사가 자막으로만 나옵니다. 들어 보기: `python -m tools.tts_sample --yes`(1문장, `--yes` 없이는 호출하지 않음, 최대 2번 호출, 무료 키만 사용).

## 실행

```powershell
cd escape\server
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env      # 키 세 개 입력 (아래 '키 세 개', 저장소에 올리지 않음)
.\.venv\Scripts\python -m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8787
```

### 키 세 개

| 키 | 하는 일 | 없으면 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 대본(이야기, 대사) 작성, Claude | 앱의 기본 이야기로 진행 |
| `GEMINI_API_KEY` (무료) | 대사 읽기(TTS)를 먼저 맡음, 무료 한도 안에서 | 처음부터 유료 키로 읽음 |
| `GEMINI_API_KEY_PAID` (유료) | 그림 생성 전부, 무료 키가 한도에 걸리거나 실패한 대사 읽기 | AI 그림 없이 앱 그림, 무료 키가 못 읽은 대사는 자막 |

- Gemini 키가 있어도 대본은 Claude가 씁니다. Gemini로 대본을 써 보려면 `STORY_PROVIDER=gemini`를 넣습니다(무료 키 사용, 시험용).
- 그림은 무료 키로 시도하지 않습니다. 그림 모델에는 무료 등급이 없기 때문입니다.

에뮬레이터의 차 앱은 `http://127.0.0.1:8787`로 접속하므로 PC로 포트를 넘겨 줍니다.

```powershell
adb reverse tcp:8787 tcp:8787
```

클라우드(Cloud Run, Fly.io, Render 등)에는 `server/Dockerfile`로 바로 배포할 수 있습니다(`STORY_TRUST_PROXY=1` 기본 포함). 배포한 서버를 쓰는 APK는 `-PstoryUrl=https://주소`로 빌드합니다.

AWS Lightsail 같은 서버 한 대에 올릴 때는 `compose.yaml`(이야기 서버 + HTTPS를 맡는 Caddy)을 씁니다. 인스턴스 만들기부터 앱 연결, 운영 명령까지 [배포_방법.md](배포_방법.md)에 있습니다.

## 모델과 정책

- 시제품 모델: 대본은 Claude `claude-opus-5-5`(`ANTHROPIC_API_KEY`), 그림은 Gemini `gemini-nano-banana-2.1`(`GEMINI_API_KEY_PAID`), 대사 읽기는 Gemini `gemini-3.8-flash-tts`(무료 키 먼저, 그다음 유료 키). 정해진 JSON 틀(`json_schema`)로 받고 대본 추론 강도는 기본 `STORY_EFFORT=medium`(그림 생성 `IMAGE_EFFORT=minimal`, 지금 그림 모델은 `low`를 받지 않음)으로 품질과 대기 시간의 균형을 맞춥니다. Google 쪽이 붐비거나 분당 횟수 제한에 걸리면 몇 초 뒤 최대 두 번 다시 요청합니다.
- 작성기(`app/writer.py`)는 바꿔 끼울 수 있게 나뉘어 있습니다. `STORY_PROVIDER=gemini`로 Gemini `gemini-3.6-flash`(무료 키)로 바꿀 수 있고, 모델 이름은 `STORY_MODEL`로 바꿉니다. 어떤 모델이 쓰든 같은 검사기를 거칩니다.
- 출시 전 교체: Gemini API 약관은 18세 미만을 대상으로 하거나 18세 미만이 이용할 가능성이 높은 서비스에 API를 쓰는 것을 허용하지 않습니다. 그래서 실제 출시 때는 Pleos 차량 인앱 LLM(앱용 SDK가 공개되면) 또는 미성년자 서비스를 허용하는 제공사(예: Anthropic, 안전장치를 갖추는 조건)로 작성기를 바꿉니다.
- 그림은 결제를 켠 유료 키로 부르므로 보낸 입력과 출력이 Google의 제품 개선에 쓰이지 않습니다. 대사 읽기는 무료 키를 먼저 쓰는데, Gemini 무료 등급에서는 보낸 입력과 출력이 Google의 제품 개선에 쓰일 수 있습니다. 그래서 TTS에는 검사를 통과한 대사 문장만 보냅니다. 서버는 어느 모델에도 정답 키, 나이 단계, 계절, 가족이 적은 장소와 이야기 종류만 보내고 아이에 대한 정보는 보내지 않습니다. 시간대는 보내지 않고, 창고에 쌓는 이야기를 쓸 때는 바깥 기온도 보내지 않습니다.
- 이야기 창고에는 Claude가 쓴 이야기만 쌓고 내보냅니다. Gemini가 쓴 이야기는 창고에 들어가지 않습니다(`STORY_LIBRARY_MODELS`).
- 아이는 AI와 직접 대화하지 않고 검사를 통과한 문장만 듣습니다. 앱은 시작 화면에 AI가 만든 이야기임을 알리고, 부모 화면에 이야기 신고 버튼을 둡니다.
